## 과제 수행 

### API Key 생성
#### Cohere: 임베딩과 리랭킹 모델      
회원 가입 후 Default로 제공되는 기본 API Key 확보    
https://dashboard.cohere.com/api-keys

#### Groq API Key   
Groq: https://console.groq.com/keys

### 사전준비
- 예제 Repository 클론  
  ```
  cd ~/workspace
  git clone https://github.com/cna-bootcamp/aistudy
  ``` 
- 프로젝트 디렉토리 작성
  ```
  cd ~/workspace
  mkdir rag
  ```

- 본인 프로젝트 디렉토리에 파일 복사   
  실습 시 한 것처럼 예제 Repository와 프로젝트 디렉토리를 vscode에서 열어 drag&drop으로 복사하세요.   
  | 예제 Repository(aistudy) | 본인 프로젝트(rag) | 비고 | 
  | ------------------------ | ----------------- | ---- |
  | AGENTS.md | AGENTS.md | 파일 복사 |
  | CLAUDE.md | CLAUDE.md | 파일 복사 | 
  | agentic-ai/textbook | textbook | 디렉토리 복사 | 
  | hands-on/10.rag/data | data | 디렉토리 복사 | 

- 본인 프로젝트에 `.env` 파일 생성 후 API Key 작성    
  ```
  COHERE_API_KEY=...
  GROQ_API_KEY=...
  ``` 
### 인덱서 개발
`prompts/rag-index.md`에 작성 후 수행하여 개발   
```
[목표]
특허법 PDF 문서를 임베딩하여 공용 벡터 DB 구축
[역할]
당신은 LangChain 전문 개발자임
[입력]
- 임베딩 대상 문서: data 디렉토리에 존재하는 PDF 문서
- RAG 교재: textbook/10.RAG.md
[처리]
- RAG 교재 이해
- 인덱싱 예제 개발
  - 파이프라인: PDF 로드 → 정제 → 청킹 → 임베딩 → 벡터 DB 저장
  - 임베딩 모델: cohere embed-v4.0
  - 벡터 DB: ChromaDB (로컬 저장, vectordb 디렉토리에 영속화)
  - 청킹: RecursiveCharacterTextSplitter (chunk_size=800, chunk_overlap=200)
  - 청킹 구분자는 나에게 추천
  - 메타데이터: source(파일명), chunk_index, total_chunks, char_count 저장
  - 설치할 라이브러리는 requirements.txt에 작성
  - 환경변수 참조: .env
- 테스트 및 버그 Fix
- README.md 작성
  - 목표 및 주요 기능 
  - 소스 코드 설명 (주요 함수, 처리 흐름)
  - 가상환경 설정 및 패키지 설치: Windows(PowerShell, Git Bash), Mac/Linux 별로 작성    
  - 실행 방법 
[출력]
- 프로그램: vector/indexing/(소스, requirements.txt, README.md)
- 벡터 DB: vectordb
[제약사항]
- MUST: 
  - requirements.txt 파일 내 주석은 영문으로 작성
  - 추가정보나 내 의사결정이 필요하면 반드시 나에게 요청 
  - LangChain 사용
  - context7 mcp 사용 
- 완료조건
  - 모든 출력 생성
  - 모든 테스트 통과 및 정상 작동 
```

### 하이브리드 검색기 개발   
`prompts/rag-hybrid-retriever.md`에 작성하고 수행   
```
[목표]
결과 품질을 높이기 위해 BM25를 이용한 Hybrid Search 예제 개발
[역할]
당신은 RAG 기반 AI앱 개발자임
[입력]
- Naive RAG 예제: vector/naive/ 
- 벡터 DB: vectordb 
- RAG 교재: textbook/10.RAG.md
[처리]
- Naive RAG 예제 분석 및 이해
- RAG 교재 이해
- 인덱싱 새로 하지 말고 기존 벡터 DB를 로드하여 검색
- 예제 개발 
  - BM25 인덱싱 프로그램 개발: 
    - kiwi 라이브러리 사용   
    - 인덱스 디렉토리: bm25
  - 하이브리드 검색기 개발:
    - 벡터 검색 + BM25 검색을 EnsembleRetriever로 결합
    - 검색기별 가중치는 나에게 추천
  - 설치할 라이브러리는 requirements.txt에 작성 
  - LLM 모델은 Groq LPU의 openai/gpt-oss-120b 모델 사용 
  - 환경변수 참조: .env
- 테스트 및 버그 Fix 
- README.md 작성
  - 목표 및 주요 기능
  - 소스 코드 설명 (주요 함수, 처리 흐름)
  - 가상환경 설정 및 패키지 설치: Windows(PowerShell, Git Bash), Mac/Linux 별로 작성    
  - 실행 방법 
- 기본RAG와 품질 차이 비교 

[출력]
- BM25 인덱싱 프로그램: vector/bm25-indexing/(소스, requirements.txt, README.md)
- BM25 인덱스 디렉토리: bm25
- 검색기 프로그램: vector/hybrid-search/(소스, requirements.txt, README.md)

[제약사항]
- MUST:
  - (중요) requirements.txt 파일 내 주석은 영문으로 작성
  - 'EnsembleRetriever'는 langchain_classic.retrievers에 있는 것 사용 
  - 추가정보나 내 의사결정이 필요하면 반드시 나에게 요청 
  - LangChain 사용
  - context7 mcp 사용 
- 완료조건
  - 모든 출력 생성
  - 모든 테스트 통과 및 정상 작동 
```

[역할]
당신은 RAG 기반 AI앱 개발 전문가임
[입력]

- BM25 인덱스: bm25

## 과제 제출 방법 
- 본인 프로젝트 Git Push    
  아래 프롬프트에서 Git Organization 이름을 본인 것으로 변경하여 수행    
  ※ 기존에 플러그인 개발한 Repository와 동일한 Organization으로 지정    
  ```
  Organization {본인 Git Organization}에 Private Repository 'rag'를 생성하고 푸시  
  ```
- [9회차 과제 제출 문서](https://docs.google.com/spreadsheets/d/1CJ_Qe3EGLEkPSaHa963yFGzZRXBrC90o/edit?usp=drive_link&ouid=110516422607493163049&rtpof=true&sd=true)에 Git Repository 주소와 배운점/느낀점 작성    

> **※ 주의사항**   
> - 구글 드라이브 문서에 고객 정보, 회사 내부 기밀정보 등 **보안 위배/의심 정보 작성 금지**   
> - Git Repository는 반드시 **Private Repository**로 만드십시오.
