# 3회차 과제 평가 피드백 — 류승재

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 이전 `경로 또는 텍스트, 형식 무관`이 `**/*.yaml`·`**/*.tf` 글롭과 `30파일 또는 4,000줄` 상한으로 계량화됨 (구체성)
- 단일 리뷰어 역할이 승재·민호·서연·지훈 4인 분담으로 확장되고 `협업형 병렬 위임`이 명시됨 (업무배분)
- 조치안이 `복붙 가능한 YAML·Dockerfile 스니펫과 삽입 앵커`와 `적용 순서` 블록으로 즉시 적용 가능해짐 (실용성)
### 보완할점
- 완료조건의 `outputs/infra-review-result.md`가 [출력]의 타임스탬프 파일명과 불일치해 검증 불가 (실용성)
- 반환 스키마 `확신도` 필드의 값 범위·판정 기준 미정의로 에이전트별 표기 편차 위험 (구체성)
- 지훈의 정리 단계에 대응하는 `subagent_type` 명시가 없어 4단계 실행 주체가 불명확함 (업무배분)

## 설명
### 구체성
- 잘된점: 기존 프롬프트의 `probe 유무`·`형식 무관` 수준 서술이 임계값·판정축으로 대체됨. 입력 한도를  
  `30파일 또는 4,000줄 초과 시 읽지 않고 즉시 중단`으로, 하네스 한도를 `병렬 Agent ≤ 2`,  
  `서브에이전트 1건당 5분, 스킬 전체 15분 상한`, `항목 30건·8,000자 이내`로 수치화함.  
  판정 기준도 심각도 6항의 `상/중/하` 조건문, 시급성 `즉시`/`이번 스프린트`/`백로그`, 공수 `S`/`M`/`L`,  
  `QoS 클래스`(Guaranteed/Burstable/BestEffort) 판정, PSS `baseline축`/`restricted축` 분리로 명시됨
- 보완할점: 반환 스키마 `[{위치, 심각도, 유형, 근거, 조치안, 확신도}]`에서 `확신도`만 값 집합이 미정의됨.  
  → 심각도·시급성·공수처럼 `확신도: 상/중/하(상=해당 라인 직접 확인, 중=필드 추론, 하=추정)` 형태로 열거하고  
  `하`인 경우 `"추정"으로 표기함` 규칙과 연결할 것. 파일 유형 표의 K8s manifest 행만  
  `리소스·probe·HA·PDB·종료·분산 / PSS·RBAC·시크릿·노출면` 요지로 축약되어 Dockerfile·Terraform 행의 필드 나열  
  수준과 상세도가 어긋나므로 2단계 상세 항목과 동일한 필드명으로 통일할 것
### 실용성
- 잘된점: 산출물이 `마크다운 파일: outputs/infra-review-{대상}-{YYYYMMDD-HHMM}.md`로 확정되고  
  `기존 파일을 덮어쓰지 않음`이 명시되어 별도 가공 없이 사용 가능함. 이전 프롬프트에 없던  
  `ID: INFRA-<STB|SEC|BP>-NNN` 고정으로 티켓화·델타 비교가 가능해지고, `해결 N / 잔존 N / 신규 N` 델타 표기,  
  `실패 폴백`의 `1회만 재호출`, 타임아웃 시 `남은 결과로 리포트를 생성`이 중단 없는 자동 진행을 보장함
- 보완할점: 완료조건이 `outputs/infra-review-result.md 가 실제 생성되고`로 기술되어 [출력]의 타임스탬프 파일명과  
  불일치함(이전 프롬프트의 고정 경로가 잔존한 것으로 보임). 실제 생성 파일이 아닌 경로를 확인하므로 완료조건이  
  항상 미충족 판정되어 검증이 성립하지 않음. → `outputs/infra-review-{대상}-{YYYYMMDD-HHMM}.md 중 최신 파일에  
  총평·발견 표·점검 매트릭스·점검 범위 4블록이 비어 있지 않음을 Read로 확인함`으로 교정할 것.  
  델타 표기의 `직전 리포트와 ID 를 대조해`도 직전 리포트 탐색 규칙(글롭 패턴 + 타임스탬프 최댓값)이 없어  
  첫 실행·다중 대상 시 대조 대상이 불확정이므로 탐색 규칙과 `직전 리포트 없음 시 델타 생략` 분기를 추가할 것
### 역할별 팀원 배분
- 잘된점: 기존 `[역할]`이 `인프라 구성 리뷰어임` 단일 서술이던 것을 4인 분담으로 전환함. AGENTS.md 경력·성향과  
  배정이 키워드 단위로 대응됨 — 민호 `쿠버네티스 SRE 8년`·`안정성 중심`은 `민호(안정성): 리소스  
  requests/limits 및 QoS 클래스 판정`에, 서연 `클라우드 보안 7년`·`RBAC·시크릿`은 `서연(보안): PSS 레벨 판정`·  
  `RBAC 특권상승`에, 지훈 `테크니컬 라이팅 5년`·`표로 구조화, 맨 위 총평 작성`은 `지훈에게 전달해 표·총평으로  
  정리함`에 각각 일치함. AGENTS.md의 `기본 적용`(협업형 → 파이프라인형, 불일치 시 토론형)도 2·4·5단계에 반영됨.  
  병렬화도 `민호·서연을 같은 턴에 Agent 2건으로 호출함`으로 독립 점검 영역을 동시 실행함
- 보완할점: 위임 실행 경로가 안정성·보안에만 존재함. 2단계는 `Agent(subagent_type: "infra-stability")`,  
  `Agent(subagent_type: "infra-security")` 2건만 지정하고, 4단계 `취합 결과를 지훈에게 전달해`는 호출 대상이 없음.  
  `.claude/agents/` 부재 시 `스킬을 중단`하는 규칙도 두 에이전트에만 적용되어 지훈 단계는 검증 공백임.  
  → `Agent(subagent_type: "infra-reporter")` 형태로 명시하고 미정의 시 중단 규칙에 포함할 것.  
  [역할]에서 지훈이 `베스트프랙티스(라벨·네임스페이스·이미지 핀·.dockerignore) 점검`도 담당하나 2단계 병렬 위임에  
  포함되지 않아 BP 점검 실행 시점이 불명확하므로, BP 점검을 2단계 병렬에 추가하거나(`병렬 ≤ 2` 한도 조정 필요)  
  4단계 지훈 위임 프롬프트에 명시적으로 포함할 것
