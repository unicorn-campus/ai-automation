# 3회차 과제 평가 피드백 — 김만수

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 기존 `기존 파일 삭제 후 재생성`을 `재생성 성공 후 교체`·실패 시 보존으로 대체해 조건 분기를 명시함 (구체성)
- 리서치를 `상호 독립 하위조사로 병렬 위임 후 근거·출처 기준으로 병합`으로 바꿔 병렬화를 도입함 (업무배분)
- 완료 기준을 `증거(로그·응답·지표)로 가설 채택/기각 판정`+`이력 갱신`으로 확장함 (실용성)
### 보완할점
- `오케스트레이터의 직접 실행 지양`에 모호어 '지양'이 잔존 → '금지 + 허용 예외 목록'으로 확정 (구체성)
- `disallowed-tools`의 `WebSearch`·`WebFetch`·`Bash` 금지가 리써니 역할과 충돌 → 도구 승계 규칙 명시 (업무배분)
- 재실행 게이트 질의로 개입 1건 증가 → 산출물 경과일 기준 기본값으로 무질의 진행 경로 확보 (실용성)

## 설명
### 구체성
- 잘된점: 기존 `"삭제 후 재생성" → 기존 파일 삭제 후 it-rnd-prompt-generator 스킬로 재생성`이  
  `재생성 성공 후 교체하며(선삭제로 인한 원본 유실 방지), 실패 시 기존 프롬프트를 보존하고 실패를 보고함`으로  
  대체됨. 기존 `(타당성보고서·기술가이드 등)` 예시 나열이 `문서명은 prompts/{기술}.md의 [출력] 준거`로  
  판정 근거화됨. `IT 기술 1건`·`Advisor 호출 시점(작업 전/중 최대 3회/후)`·`README.md 요약표에 1줄 추가`·  
  `prompts/{기술}.md 단일 정확 경로만`으로 건수·범위도 명시됨
- 보완할점: `증거(로그·응답·지표)로 가설 채택/기각 판정`에 지표 항목·합격선이 없어 판정이 담당자 재량에 남음.  
  → `[출력]`에 측정 지표명과 채택 임계값(예: 재현 성공률 ≥ 90%, 응답 p95 ≤ N ms)을 기재할 것.  
  `덮어쓰기·멱등 처리 포함`도 멱등 판정 조건(해시·섹션 일치 등)이 없어 검증 불가하므로 조건 서술을 추가할 것
### 실용성
- 잘된점: 기존 `it-rnd-ppt-generator 스킬로 4단계 md를 .pptx로 변환`이 `5단계에서 생성한 md 경로를 변환 대상으로  
  지정 전달함(... 하위 스킬의 전체 스캔·재질의는 해당 파일로 한정)`으로 바뀌어 하위 스킬의 대상 재질의가 제거됨.  
  산출물은 `outputs/{기술}_{문서명}_{YYYYMMDD}.md`·`poc/{기술}/`의 `research.md`·`design.md`·  
  `verification_report.md`로 경로·확장자까지 지정되어 바로 사용 가능함. 완료 기준은  
  `문서 작성·코드 실행 자체는 완료가 아님`과 `[Bad] "R&D 완료, 문서 생성함" ← ... → 기각` 예시로 검증 가능함
- 보완할점: `AskUserQuestion으로 "전체 재실행 / 특정 단계만 재검증 / 기존 산출물 재사용"을 질의함`이 신설되어  
  수동 개입이 1건 늘었고 `신선한 증거가 필요하면 재실행 권고`는 판단 기준이 없음.  
  → `HISTORY.md 기록일로부터 N일 초과 시 전체 재실행 기본 적용` 같은 무질의 기본값 규칙을 추가할 것.  
  `회사 템플릿 기반 .pptx로 변환`의 결과 확인 항목이 없으므로 `[출력]`에 슬라이드 수·템플릿 마스터 유지 확인을  
  추가할 것
### 역할별 팀원 배분
- 잘된점: AGENTS.md 접근 가능하여 멤버 서술과 대조 판정함. `리서치(리써니): 선행기술·특허 / 논문·트렌드 /  
  경쟁·대안 비교를 ... 병렬 위임 후 ... (Fact/Opinion 구분)`이 리써니 역할 `선행기술·특허 조사, 논문·기술 트렌드  
  리서치, 경쟁·대안 기술 비교`와 항목 단위로 일치함. `검증(베리)은 구현(코디)과 분리(자기검증 금지)`는 베리 성향  
  `어드버서리얼(adversarial) 검증`과 대응하고, `단계 산출물 핸드오프`·`클로니가 게이트 통과를 판정한 뒤에만  
  다음 담당자에게 위임함`으로 파이프라인형 패턴이 확정됨
- 보완할점: frontmatter `disallowed-tools`의 `WebSearch`·`WebFetch`·`Bash`가 리써니 경력  
  `WebSearch·WebFetch·context7 기반 1차 근거 수집`과 AGENTS.md `curl {URL} > .temp/{filename}` 규칙과 상충함.  
  → "금지는 본 스킬 직접 실행에만 적용, 위임 서브에이전트는 별도 도구 세트 사용"을 `[제약조건]`에 명시할 것.  
  병렬 3개 하위조사의 결과 파일 경로가 `research.md` 단일이어서 동시 쓰기 충돌 위험이 있으므로  
  `poc/{기술}/research/{하위주제}.md`로 분리 후 병합 산출물을 `research.md`로 지정할 것
