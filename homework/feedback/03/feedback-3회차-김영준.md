# 3회차 과제 평가 피드백 — 김영준

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 원본의 `핵심 요약은 3줄을 초과하지 않는다`를 `정확히 3줄(줄당 40~100자)`로 바꿔 검증 가능하게 함 (구체성)
- 단독 역할 프롬프트를 `[오케스트레이터]`·`[논문 분석가]`·`[요약 작성자]` 4단계 파이프라인으로 분해함 (업무배분)
- 완료조건에 `글자수 기준(하한·상한)이 실측으로 확인됨`을 넣어 생성이 아닌 결과 검증 수준으로 기술함 (실용성)
### 보완할점
- 판독 실패 임계값이 `90% 이상이 공백·오류`와 `텍스트 추출률 90% 미만`으로 상호 모순 → 표현 통일 (구체성)
- 병렬 처리를 전면 배제해 독립 작업인 서지정보 6항목 추출까지 순차화 → 독립 항목만 병렬 위임 (업무배분)
- `Bash(wc -m 등)로 각 섹션·불릿의 실제 글자수를 측정`의 섹션 분리 절차 부재 → 측정 명령 예시 명시 (실용성)

## 설명
### 구체성
- 잘된점: 원본의 `전문 용어는 첫 등장 시 1줄 이내로 풀어 쓴다`가 `괄호 안에 40자 이내(공백 포함) 설명을 병기`로  
  대체되어 "1줄"이라는 모호 단위가 문자수로 확정됨. `본문(서론~결론)이 30페이지를 초과해도`, `최소 1개, 최대 3개  
  표를 선정`, `연구 배경: 300~500자`, `제안 방법: 400~700자` 등 임계값·범위·건수가 단위와 함께 기재됨.  
  `Limitation/Future Work 절이 있으면 해당 절 기준으로 작성, 없으면 "논문에 명시된 한계 없음"으로 표기`,  
  `제목·저자 블록이 2건 이상 존재하면(=논문 2편 이상 합본) 첫 번째 논문만` 등 조건문 분기도 명시됨
- 보완할점: 임계값 정의가 상충함. 작업방법은 `추출 결과의 90% 이상이 공백·오류이면` 중단인데, 제약조건은  
  `텍스트 추출률 90% 미만 시 판독 실패`로 적혀 있어 전자는 추출률 10% 미만, 후자는 90% 미만을 뜻함.  
  → "추출된 문자 중 공백·오류 문자 비율 ≥ 90%(=유효 추출률 < 10%)일 때 중단"으로 한 문장으로 통일하고  
  제약조건에도 동일 문구를 복사할 것. `페이지 수 상한 처리`라는 항목명과 달리 `30페이지를 초과해도 전체를 읽되`로  
  실제 상한이 없어 컨텍스트 초과 시 판정이 부재하므로 "본문 60페이지 초과 시 섹션 단위 분할 판독 필수" 같은  
  2차 임계값과 초과 시 동작을 추가할 것
### 실용성
- 잘된점: 원본에 없던 자동 폴백·자동 검증이 들어와 수동 개입이 줄었음. `Read 도구로 판독이 안 되거나(스캔 이미지  
  전용 등) 결과가 부실하면 Bash로 pdfplumber 등 텍스트 추출 도구를 실행해 대체`, `불일치·근거 누락·분량 초과가  
  발견되면 해당 단계(분석가 또는 작성자)로 반려하고 재작업을 위임`이 근거임. 산출물이  
  `결과 파일: ./outputs/논문요약_{파일명}.md`로 확정되고 `공백은 언더스코어(_)로 치환` 등 파일명 규칙까지 정해져  
  별도 가공 없이 공유 가능함. 완료조건도 `실험 결과 섹션에 표가 1개 이상 포함됨`,  
  `[출력]의 섹션별 글자수 기준(하한·상한)이 실측으로 확인됨`, `오케스트레이터의 근거 대조(4단계)를 통과함`으로  
  생성 여부가 아닌 검사 결과 기준으로 기술됨
- 보완할점: 측정 절차가 실행 불가 수준임. `작성 후 Bash(wc -m 등)로 각 섹션·불릿의 실제 글자수를 측정`은  
  마크다운 1개 파일에서 섹션·불릿을 분리해 세는 방법이 없어 `wc -m` 단독으로는 파일 전체 글자수만 나옴.  
  → "`awk`로 `##` 헤더 기준 분할 후 섹션별 `wc -m` 실행" 수준의 명령 예시 또는 `scripts/count.py` 같은 보조  
  스크립트 경로를 [입력정보]에 추가할 것. `반려하고 재작업을 위임한다`에 재시도 상한이 없어 검증 실패 시 무한  
  반복 위험이 있으므로 "동일 항목 반려는 최대 2회, 초과 시 해당 항목을 '미검증'으로 표기하고 종료"를 완료조건에 추가할 것
### 역할별 팀원 배분
- 잘된점: 원본은 `너는 ... AI/ML 분야 논문 리뷰 전문가다` 단일 역할 단독 수행이었으나, 스킬은  
  `[오케스트레이터] 위임 준비` → `[논문 분석가] 판독 및 근거 추출 — Agent 도구로 위임` → `[요약 작성자] 요약  
  보고서 작성 — Agent 도구로 위임` → `[오케스트레이터] 근거 검증 및 확정`으로 4단계 분담됨.  
  `오케스트레이터가 아래 파이프라인 순서로 각 단계를 팀원에게 위임하고, 각 단계 산출물을 다음 단계 입력으로  
  전달한다`로 파이프라인형이 명시되고 배정이 AGENTS.md 서술과 대응됨 — 논문 분석가 `원문에 없는 내용을 추가하지  
  않음` ↔ `원문 근거(페이지 또는 섹션 번호)를 병기하여 추출`, 요약 작성자 `전문 용어는 첫 등장 시 짧게 풀어 씀` ↔  
  `괄호 안에 40자 이내 ... 병기`. 1단계가 `"논문 분석가" 페르소나(AI/ML 분야 논문 리뷰어 10년 경력 ...)`로  
  호출 페르소나를 명문화한 점도 강점임
- 보완할점: 병렬 처리가 도입되지 않았고 오히려 두 곳에서 명시적으로 배제됨 — `각 단계가 이전 단계의 산출물을  
  입력으로 필요로 하므로 병렬 처리 대상이 아님`, `항목별로 나누어 병렬 위임하지 않고, 분석가 1인이 통독한 뒤  
  순차로 추출한다`. 단계 간 의존성 근거는 타당하나 `서지 정보를 확인한다: 제목/저자 ... 6항목을 표로 정리`는  
  본문 4개 항목 추출과 상호 근거 참조가 없는 독립 작업이므로 순차화 필요가 없음.  
  → 2단계를 "2-a 서지정보 추출(병렬)"과 "2-b 본문 4항목 추출(순차)"으로 분리해 2-a만 별도 위임하고, 병렬 배제  
  문구를 "본문 4항목 간에는 병렬 위임하지 않음"으로 범위를 좁힐 것. `해당 단계(분석가 또는 작성자)로 반려하고`도  
  판단 기준이 없으므로 "수치·근거 불일치는 분석가, 분량·표현 위반은 작성자"처럼 결함 유형별 매핑을 명시할 것
