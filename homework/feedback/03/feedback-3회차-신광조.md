# 3회차 과제 평가 피드백 — 신광조

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- `perf.env`에 CPU·컴파일러·구현종류·통계방식 4요소 기재, `재시도 1회까지만(합 2회)` 등 임계값을 못박음 (구체성)
- 14단계 전부에 `[계층형]`·`[파이프라인형]`·`[협업형]`·`[토론형]` 패턴과 담당 팀원을 1:1로 지정함 (업무배분)
- `변경 0건` 시 `xlsx`·`pptx`·카드 재생성을 생략하는 비용 게이트로 반복 실행 부담을 낮춤 (실용성)
### 보완할점
- `features`·`standardization`이 자유 문자열이라 표준화단계 diff 오탐 여지 있음 → 열거값·길이 상한 부여 (구체성)
- 커밋이 `사용자 요청 시`로 한정돼 `git show HEAD:data/snapshot.json` 폴백이 무력화 가능 → 자동 커밋 승격 (실용성)
- 동시 `Task` 총량 상한이 없어 `자료수집가 2인` 배치가 G1 ~ G4 팬아웃과 충돌 가능 → 상한 4개 명시 (업무배분)

## 설명
### 구체성
- 잘된점: 모호어를 검증 가능 수치로 대체함. `perf.env`에 `CPU 모델·클럭 / 컴파일러 / 구현종류(C ref·AVX2) /  
  통계방식(median·avg, 반복횟수) 4요소를 기재함`, 슬라이드 `기본 7±1장(6~8장)`,  
  `실패(타임아웃·비200·본문 공백) 시 동일 URL 재시도 1회까지만(합 2회)`으로 임계값·건수를 확정함.  
  판정 기준도 `confidence 판정기준: high=공식 1차 본문 직접 확인 / medium=공식 목록·요약만 확인 /  
  low=접근 불가·2차 배경만`과 status 표준값, 6구분 diff 판정으로 조건문화됨.  
  이전 프롬프트의 `단위·측정환경을 통일하고`라는 서술 대비 측정 항목·정규화 규칙이 실행 가능 수준으로 확정됨
- 보완할점: `standardization`·`features`에 열거값·길이 상한이 없는데 diff는 `(5) 표준화단계: standardization이  
  이전≠현재`로 문자열 동등 비교임. 서술 어투만 바뀌어도 변경으로 계상될 수 있음.  
  → `standardization`을 `FIPS203 대응|FIPS204 대응|KCMVP 등재|KpqC 표준|(미확인)` 등 열거값 + 비고 필드로 분리하고,  
  `features`는 diff 대상에서 제외하거나 `최대 200자·불릿 3개 이내` 상한을 둘 것.  
  `구현 병기(ref/AVX2) 순서·구분자만 다른 경우는 동일값으로 간주`도 판정 절차가 없으므로  
  `구현명:숫자` 토큰 분해 후 집합 비교로 판정한다는 절차를 명시할 것
### 실용성
- 잘된점: 기준선을 `data/snapshot.json` → `git show HEAD:data/snapshot.json` → `git show HEAD:catalog/README.md`  
  → `이전 기준 없음(최초 실행)` 4단 폴백으로 자동 확보하고, `기수집·정규화 완료 항목은 스냅샷 값을 재사용함  
  (중복 fetch·재정규화 금지)`로 재실행 비용을 줄임. 산출물은 `compare/kpqc-비교표.xlsx`(KEM/전자서명 시트 분리)·  
  `slides/kpqc-현황.pptx`를 스킬 위임으로 바로 쓰는 형식으로 지정함. 완료조건도  
  `snapshot.json이 유효 JSON으로 파싱되고 algorithms[].name이 유일`, `변경 건수 합(신규+탈락+변경) = 표 행 수와 일치`로  
  생성 여부가 아닌 실행 결과 확인 수준임
- 보완할점: `Git(L5, 사용자 요청 시)`로 커밋이 선택 사항인데 기준선 폴백 2·3순위는 `git show HEAD:...`에 의존함.  
  커밋 미지시 회차에 작업트리 `data/snapshot.json`이 유실되면 기준선이 3순위로 강등되어 `수치 diff 불가`가 됨.  
  → 완료 후 스냅샷 자동 커밋을 기본 동작으로 두거나 `data/snapshot-{status_reconfirmed}.json` 이력본을 남기고  
  폴백 2순위로 삽입할 것. `xlsx`·`pptx` 위임 실패(스킬 미설치·생성 실패) 처리 규칙도 없으므로  
  실패 시 마크다운 비교표만 확정하고 미생성 사유를 보고하는 분기를 완료조건에 추가할 것
### 역할별 팀원 배분
- 잘된점: 이전 프롬프트는 `자료수집가를 병렬로 팬아웃하여` 1개 문구뿐이었으나, 스킬은  
  `오케스트레이터(총괄·검수) / 자료수집가(병렬 수집) / 암호분석 정리가(정규화·스냅샷·diff·판정) / 문서편집가`  
  4역할을 전 단계에 배정함. AGENTS.md 경력 서술과의 대응도 성립함 — 자료수집가 `공식 출처를 넓게 병렬 수집` ↔  
  `G1 KpqC 공식 / G2 NIST PQC / G3 KISA·국정원·국보연 / G4 알고리즘 명세·ePrint`,  
  암호분석 정리가 `격자·부호·해시기반 PQC 구현/분석` ↔ `보안 파훼·공격 성립 판정은 ... 암호분석 정리가가 최종 판정`.  
  병렬화도 `1)과 2)는 상호 독립 Read이므로 병렬 가능`, `Task로 KEM군·서명군 2갈래를 병렬 작성함`,  
  `수집 완료분부터 흘려보내 대기시간을 최소화함`으로 도입됨
- 보완할점: 5)는 `Task로 자료수집가 2인을 상반 배치함`이나 동시 실행 `Task` 총 상한이 없어 3)의 `4개 출처군으로  
  동시 기동함`과 겹치면 과도한 동시 호출이 발생 가능하고, 논쟁 항목 다건 시 처리 순서도 없음.  
  → `동시 Task 최대 4개`, 논쟁 항목은 `status를 뒤집는 항목 우선, 회차당 최대 N건 처리 후 잔여는 다음 회차 이월`을  
  명시할 것. 9) ~ 13) 5개 산출물이 모두 문서편집가 단독 담당이라 10) ~ 12)가 `(병렬)` 표기임에도 실제 병렬 주체가  
  불명확하므로, 문서편집가를 `카탈로그`/`표·슬라이드`로 분할 기동할 것
