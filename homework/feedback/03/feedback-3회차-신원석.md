# 3회차 과제 평가 피드백 — 신원석

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 검증 포인트 8종을 `단일 재직 기간 12개월 미만`·`공백 2개월 초과` 등 수치 임계값으로 정의함 (구체성)
- `[병렬, 동일 이력서 독립 판독]` 4단계와 6단계 검수 2인을 동시 호출해 파이프라인 속도를 높임 (업무배분)
- 완료 기준 6개를 `총 질문 수 34개 이상`·`합계 30점 만점` 등 카운트 가능 조건으로 기술함 (실용성)
### 보완할점
- 리스크 등급 `상/중/하` 배치 규칙은 있으나 등급 판정 임계값 미정의로 배치가 흔들릴 수 있음 (구체성)
- `agent.md` 멤버가 오케스트레이터 1인뿐이어서 서브역할 5종이 팀 명단과 불일치 → 명단 등재 (업무배분)
- 재작업 2회 후 `미해결 항목을 결과 보고에 그대로 명시함`이라 면접관 수동 검수가 남음 (실용성)

## 설명
### 구체성
- 잘된점: 이전프롬프트의 `[처리]` 섹션이 완전 공란이고 `이력서의 경력을 보고 요약해서 질문지를 작성 한다` 수준의  
  모호 지시였던 것을, 검증 포인트 8종에 `최근 5년 내 3개사 이상 또는 평균 재직 24개월 미만`,  
  `2초→500ms 등 개선 수치의 측정 방법` 같은 판정 가능 조건으로 대체함. 단위·임계값도  
  `PDF는 페이지 수 10 이하, 텍스트 파일은 300줄 이하`, `맞춤 검증 질문이 3~6개`, `한 줄 120자 이내`로 명시됨.  
  분류 기준은 `리스크 등급 '상'은 3번 섹션, '중·하'는 6번 섹션`, `직접 수행 조건(2개 전부 충족)`,  
  `0건/1건/2건 이상` 3분기로 조건문화됨. 개월 수 계산도  
  `시작월과 종료월을 모두 포함하여 계산함(예: 2022.03~2022.10 = 8개월)`로 예시까지 고정함
- 보완할점: `리스크 등급(상/중/하)`을 배치·압축의 핵심 축으로 쓰면서 등급 판정 자체의 기준이 없음.  
  `등급 '상'을 3~6개로 압축하고`라고만 하여 무엇이 '상'인지 판단이 하위 에이전트 재량에 남음.  
  → 검증 포인트 8종별 등급 매핑표를 추가할 것(예: 재직 6개월 미만 또는 이력서 내부 불일치 = 상,  
  공백 2 ~ 6개월 = 중, 그 외 = 하). `상위 6건만 3번 섹션에 채택`의 '상위' 정렬 키도 미정의이므로  
  정렬 우선순위(등급 → 최근성 → 지원분야 관련도)를 명시할 것
### 실용성
- 잘된점: 산출물이 `output/{면접자}질문지.md` 단일 파일로 고정되고, `각 질문 아래에 면접관 기입용 → 행을 1줄  
  배치함`, `필수 역량 6종 5점 척도 배점란(합계 30점 만점)`, `채용 추천 4택(강력추천·추천·보류·부적합)`으로  
  면접장에서 별도 가공 없이 바로 쓸 수 있음. 이전프롬프트가 출력 경로 한 줄만 있던 것과 달리  
  `동명 파일이 있으면 덮어쓰지 않고 사용 중이지 않은 최소 번호를 붙여` 저장하고,  
  `0건: 즉시 중단하고 AskUserQuestion으로 경로 재확인` 분기로 사용자 재지시 횟수를 줄임.  
  완료조건은 `저장 후 파일 존재와 섹션 구성을 실제로 확인함`과 9단계 `판단 증거` 보고로 실행 결과 확인 수준임
- 보완할점: `재작업은 최대 2회. 2회 후에도 잔여 지적이 있으면 미해결 항목을 결과 보고에 그대로 명시함`은  
  정직하지만, 면접관이 어느 항목을 직접 손봐야 하는지 판단해야 하므로 수동 개입이 잔존함.  
  → 미해결 지적을 산출 파일 말미 `## 미해결 검수 사항` 섹션에 위치·유형과 함께 자동 첨부해 파일만 봐도 보정  
  지점이 드러나게 할 것. `Agent 호출은 지원자당 기본 5회 … 최대 11회`이므로 N=3 배치 시 33회까지 늘어나므로  
  4단계 2역할을 1회 호출로 통합 가능한 조건(텍스트 100줄 이하 등)을 추가해 상한을 낮출 것
### 역할별 팀원 배분
- 잘된점: 이전프롬프트가 `원문 분석가·구조화 에디터·정확성 검증가·품질 검수가`를 나열만 하고 `[처리]`가 비어  
  실제 분담이 없던 것과 달리, 이력서 분석가·리스크 검증가·질문 설계가·정확성 검증가·품질 검수가 5종에  
  `산출물: 경력 사실 카드(항목값 + 근거 위치 병기)`처럼 산출물 규격까지 부여함. 협업 패턴은 추출(병렬 2인) →  
  설계(순차 1인) → 검수(병렬 2인) → 오케스트레이터 게이트의 파이프라인+계층 혼합으로,  
  `[순차, 4단계 양쪽 산출물 의존]`처럼 의존관계가 작업 성격과 대응됨. `agent.md` 멤버가 오케스트레이터 1인뿐인  
  제약을 스킬이 `서브 역할 5종은 agent.md 멤버 섹션에 미정의 상태이므로 … Agent 프롬프트에 인라인 주입하여  
  호출함`으로 자체 고지한 점도 정직한 처리임. 병렬화는 4·6단계 동시 호출과 `동시 실행 상한 3명`으로 적용됨
- 보완할점: 팀 명단의 오케스트레이터 역할이 `VPN·PQC 시장조사 멀티 에이전트 오케스트레이션 총괄`로 이력서  
  도메인과 무관해, 스킬이 `인라인 주입`으로 우회하는 구조임. → AGENTS.md에 이력서 분석가·리스크 검증가 등 5종의  
  프로파일·경력을 등재하고 스킬은 멤버 참조만 하게 하여 중복 정의를 제거할 것.  
  5단계 `질문 설계가`가 단일 순차 병목이므로, 3번 섹션(맞춤 검증)과 5번 섹션(역량별 상세)을 독립 작업으로 분리해  
  2인 병렬화하고 오케스트레이터가 섹션 순서로 병합할 것
