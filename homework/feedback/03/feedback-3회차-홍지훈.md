# 3회차 과제 평가 피드백 — 홍지훈

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 이전 `문서가 낡았거나 비어 있는 영역을 식별`을 노후도 판정 1·2순위 규칙과 `6개월 경과` 임계값으로 대체함 (구체성)
- 분량 통제를 `약 60행` 기준에서 `섹션별 항목 수 상한 ... 합계 28항목 이내`로 전환함 (구체성)
- `수집 (4개 관점 병렬, 관점별 서브에이전트 1인 배정)`에 `반환 규약`을 신설해 분담 결과가 회수되게 함 (업무배분)
### 보완할점
- 4개 관점이 AGENTS.md 멤버(커니·루디·유비·도담·베라)의 담당 영역과 무대응 → 관점별 페르소나 정의 (업무배분)
- `작성과 검증은 분리된 패스로 수행`에 반해 검증 패스 수행 주체 미지정 → 베라 배정 필요 (업무배분)
- 완료조건 3항목이 이전프롬프트와 동일해 신설 기준의 실행 결과 검증이 누락됨 → 완료조건 3항 추가 (실용성)

## 설명
### 구체성
- 잘된점: 이전프롬프트의 `문서가 낡았거나 비어 있는 영역을 식별`이라는 모호 지시를  
  `1순위: 본문 메타데이터의 날짜 행 (| 날짜 | YYYY-MM-DD | 등)`, `2순위: 파일명에 포함된 YYYY-MM-DD`,  
  `판정 가능한 문서 중 6개월 경과분을 노후로 표기`, `파일 mtime·git 이력 사용 금지`로 대체함.  
  `관점당 최대 10개`, `합계 28항목 이내`, `판정 가능: {n}/{전체}건 ({비율}%)`로 건수·비율 단위도 명시됨.  
  `판정 불가`·`수집 실패`·`노후` 3분류와 `빈 응답이거나 형식이 어긋나면 1회 재요청` 조건문으로 분류 기준을 세움
- 보완할점: `관련도 판정 기준: {task}의 키워드·대상 파일·인접 모듈과 연결되면 채택`에서 `인접 모듈`의 판정 범위가  
  미정의됨. → import·호출 관계 1홉 이내 등 탐색 깊이 임계값을 명시할 것.  
  `템플릿·목차는 문서가 아니므로` 제외 대상을 `template.md`, `*-TEMPLATE.md`, `README.md`로 열거했으나  
  `[입력정보]`의 대체 입력에 `{repo}/README.md`가 포함되어 상충하므로 대체 입력일 때만 예외를 허용하는 조건을  
  추가할 것
### 실용성
- 잘된점: `반환 규약: 각 서브에이전트는 발견 항목 목록을 **응답 본문으로** 반환`, `파일 기록·진행 요약만 남기고  
  종료하는 것 금지`로 결과 회수를 위한 수동 파일 추적을 제거함. `빈 응답이거나 형식이 어긋나면 1회 재요청`,  
  `수집 실패를 "해당 사항 없음"으로 처리하지 말 것`으로 사용자 재실행 지시 없이 실패를 자동 처리·표면화함.  
  산출물은 `브리핑 파일: .omc/briefs/{repo}-{YYYYMMDD}.md`와 6개 섹션 구성 순서,  
  `대화창에는 한 줄 요약·함정 2개 섹션만 요약 출력`으로 바로 사용 가능한 형식을 명시함
- 보완할점: `완료조건`이 `출력 경로에 브리핑 파일이 생성됨`, `모든 항목에 출처 경로가 존재함`,  
  `대화창에 요약 2개 섹션이 출력됨`으로 이전프롬프트와 완전히 동일하여, 신설된 `합계 28항목 이내`와  
  `문서 공백` 3행 고정 형식의 준수 여부를 검증하지 못함. `[출력]`에 `분모가 0이거나 비어 있으면 판정 자체가  
  실패한 것으로 식별 가능`이라 명시했으나 완료조건에 대응 항목이 없어 실패 식별이 실행되지 않음.  
  → 완료조건에 "섹션별 항목 수 실측값이 상한 이내이며 합계 28 이하임", "`문서 공백` 3행이 모두 분모를 포함하고  
  분모>0임", "`수집 실패` 관점 수를 명시함" 3항을 추가할 것
### 역할별 팀원 배분
- 잘된점: `수집 (4개 관점 병렬, 관점별 서브에이전트 1인 배정)`으로 구조·결정·함정·규칙의 상호 독립 작업을  
  병렬화하고, 이전프롬프트에 없던 `반환 규약`(`항목마다 출처 파일 경로 병기, 관점당 최대 10개`)과 실패 시  
  `1회 재요청` 계약을 추가하여 분담 결과의 회수 가능성을 확보함. `보조 역할: [작업방법]의 수집·검증 단계에서  
  서브에이전트로 분담`을 `[역할]`에 신설하여 분담을 역할 수준에서 선언함
- 보완할점: AGENTS.md 멤버는 `커넥터 전담 | 커니`, `루틴 전담 | 루디`, `컴퓨터유즈 전담 | 유비`,  
  `문서화(교재) 전담 | 도담`, `검증 전담 | 베라`인데, 스킬의 4개 관점(구조·결정·함정·규칙)과 담당 영역·경력  
  서술이 전혀 대응되지 않아 배정이 익명 서브에이전트에 머묾. 특히 AGENTS.md의 `작성(도담·기능 전담)과  
  검증(베라)은 반드시 분리된 패스로 수행. 오케스트레이터는 동일 컨텍스트에서 자가 승인하지 않음`에 반해, 스킬은  
  `검증 (수집과 분리된 별도 패스)`라고만 적고 수행 주체를 지정하지 않아 자가 승인 여지가 남음. `브리핑 작성`  
  단계도 담당자 미지정임. → 검증 패스를 `베라(증거 기반 검증가, 8년차 QA)`에 배정하고 `브리핑 작성`을  
  `도담(명사체 기술문서·교재 편집 전문)`에 배정하여 파이프라인형(수집 병렬 → 선별 → 검증 → 작성) 단계별  
  담당자를 명시할 것. 4개 관점에도 최소한 각 관점의 판정 전문성 서술을 추가할 것
