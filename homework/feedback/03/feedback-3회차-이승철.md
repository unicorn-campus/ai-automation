# 3회차 과제 평가 피드백 — 이승철

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 임계값을 전부 수치화함 — `소스 파일 15개 이상 / 독립 모듈 4개 이상 / 총 8,000줄 초과`, `기본 20MB/s` (구체성)
- 병렬화 축을 `문서(기능·모듈) 단위로 한정`하고 `동시 최대 4개`·barrier·안티패턴까지 규정함 (업무배분)
- 완료조건을 `lint_mermaid.py 치명오류 0건`·`끊어진 링크 0건` 등 검증 실행 결과로 규정함 (실용성)
### 보완할점
- 서브에이전트가 `범용 분석 서브에이전트(Agent)` 단일 유형뿐이어서 전문성 분화 없음 → 역할별 프로파일 부여 (업무배분)
- `scripts/assemble.py`·`manifest.py` 부재 시 폴백 미기술 → 스크립트 미존재 경로 정의 필요 (실용성)
- `산출 규모가 애매하면`·`대상이 모호하면`·`이득이 미미하면` 등 잔여 모호어 3건 → 판정식 부여 (구체성)

## 설명
### 구체성
- 잘된점: 모호어를 판정식으로 대체한 사례가 다수임 — `대규모 판정 기준(하나라도 충족 시 대규모): 소스 파일 15개  
  이상 / 독립 모듈 4개 이상 / 총 8,000줄 초과`, `Grep 히트 구간 ±30줄 부분 Read만, 합계 3,000줄 이내`,  
  `문서 1건당 다이어그램 최대 10개, 다이어그램 1개당 노드 최대 15개`, `챕터 5~12개`, `min_mbps<임계, 기본 20MB/s`로  
  측정 단위·임계값·건수가 모두 명시됨. 분류 기준도 `HIGH=버그·보안 위험, MED=성능·유지보수 영향,  
  LOW=스타일·가독성`, `독립 문서 기준(하나라도 해당): 관련 파일 3개 이상 / 자체 상태 머신·프로토콜 보유 /  
  에러·복구 경로가 독립적`, 다이어그램 `완성 판정: (a)~(d)` 4조건으로 검증 가능하게 기술됨.  
  이전 프롬프트의 `A4 3페이지 이내 — 공백 포함 6,000자` 수준 대비 판정 기준 밀도가 크게 상승함
- 보완할점: 사용자 확인 분기의 발동 조건에 모호어가 잔존함 — `산출 규모가 애매하면(짧은 답으로 충분해 보이면)`,  
  `대상이 모호하면 사용자에게 어느 디렉토리를 갱신할지 1줄 확인`, `소규모(문서 1~2건)라 전환 이득이 미미하면`.  
  → "애매" 대신 `기능 인벤토리 도출 결과 대상 심볼 3개 이하 ∧ 관련 파일 2개 이하 → 요약 답변 제안`,  
  "모호" 대신 `생성 서명 보유 docs* 후보 2개 이상 ∧ 최신 갱신 시각 차이 24시간 이내 → 확인`처럼 수치 판정식으로  
  대체할 것. `동시 최대 4개`의 근거(컨텍스트·토큰 한도)도 미기재이므로 산정 근거 1줄을 병기할 것
### 실용성
- 잘된점: 수동 개입이 스크립트로 대체됨 — `scripts/(assemble.py 조립 · lint_mermaid.py 검증 · manifest.py 증분  
  스킵 · probe_io.py 매체 속도 프로브)`, `이 자산·스크립트를 매번 재작성/재다운로드하지 말고 번들을 그대로 쓸 것`.  
  산출물은 `저장 위치: 프로젝트 최상단 폴더 바로 아래 docs/`, `docs*/function/`·`docs*/assets/` 3분류와  
  `외부 리소스 참조 금지` 기반 오프라인 자립 HTML임. 완료조건도 `대조 4항목`+`추가 점검`(⑤ ~ ⑬),  
  `치명오류 0건`, `끊어진 링크 0건`, `안 바뀐 문서는 재작성되지 않았는지(증분 스킵 확인)`와 최종 보고의  
  `대조표(항목 | 기준값 | 문서값 | 일치)` 요구로 실행 결과 확인 수준임
- 보완할점: 번들 의존의 실패 경로가 비대칭임. 자산은 `없을 때만 CDN 1회 다운로드 폴백`이 있으나  
  `scripts/assemble.py`·`lint_mermaid.py`·`manifest.py`·`probe_io.py`가 없을 때의 동작은 미정의로,  
  스크립트 미배포 환경에서 `치명오류 0을 완료 조건에 포함`을 충족할 수 없음.  
  → `[제약조건]`에 "scripts/ 부재 시 → lint는 정규식 자체 점검으로 대체, manifest는 JSON 직접 기록, 프로브 생략 후  
  in-place 고정" 폴백 3줄을 추가할 것. `AskUserQuestion`(10건 초과·5건 초과) 게이트도 비대화형 실행에서 무응답 시  
  기본값이 없어 정지 가능하므로 `무응답 또는 비대화형 실행 시 상위 5건 자동 진행`을 명시할 것
### 역할별 팀원 배분
- 잘된점: AGENTS.md는 `(레포에 AGENTS.md 없음)`으로 접근불가여서 기준 2는 스킬 내 서브에이전트·역할 서술만으로  
  판정함. 배분 판정을 절차 0단계로 선행 배치함 — `0. 업무배분 판정 (분석 착수 전 1회)`,  
  `본 작업은 팀원 전문 분야(커넥터/루틴/브라우저)와 무관하므로 오케스트레이터가 직접 수행. 코니/루티/브라우니  
  위임 금지`로 위임 대상과 제외 근거를 명시함. 협업 패턴은 계층형 fan-out+병합으로 작업 성격과 대응됨 —  
  `문서 1건 = 서브에이전트 1개, 중복 배정 금지`, `barrier: 모든 서브에이전트 완료 후에만 HTML 조립`,  
  `HTML 조립·스타일 통일은 규모와 무관하게 오케스트레이터 단독 수행`. 안티패턴도 규정함 —  
  `한 문서 내부를 역할별로 쪼개 병렬화하지 말 것`. 서브에이전트 출력 계약 5항목(① ~ ⑤)까지 규정함
- 보완할점: 위임 대상이 `기능·모듈 단위 범용 분석 서브에이전트(Agent)` 단일 유형이라 전문성별 분화가 없음.  
  `코니/루티/브라우니 위임 금지`로 기존 팀원은 배제했으나 대체 전문가 프로파일이 정의되지 않아, 다이어그램  
  설계(4번)·memory map(3번)·보안 특이사항(⑤) 등 성격이 다른 작업이 동일 역할에 뭉쳐 있음.  
  → `[작업방법] 0`에 "코드분석가(Grep 근거 수집·전이 조건 판정), 다이어그램 설계자(Mermaid·linkStyle·범례),  
  메모리맵 분석가(링커 스크립트 전담)" 3개 서브에이전트 프로파일과 담당 산출 항목을 표로 명시할 것.  
  `동시 최대 4개` 초과 후보 발생 시 대기·큐잉 규칙이 없으므로 `근거 파일 수 내림차순으로 큐잉`을 보완할 것
