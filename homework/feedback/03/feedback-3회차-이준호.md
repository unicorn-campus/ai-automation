# 3회차 과제 평가 피드백 — 이준호

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 이전 프롬프트의 `적절히 줄바꿈`을 `의미 단위 경계에서 줄바꿈` + 모호어 4종 금지로 치환한 점이 정확함
- 판정 5종(`일치`·`경미불일치`·`불일치`·`근거없음`·`과장`)에 경계 정의를 붙여 재현 가능한 채점기를 만듦
- 담당별 `허용 도구`·`금지 도구`·`쓰기 허용 경로` 3열 표로 4인 역할 경계를 파일 단위까지 못박음
### 보완할점
- `호출 상한 12회`와 `배치 단위 20쪽`이 200쪽 논문에서 충돌해 정상 논문이 중단 처리됨 (실용성)
- 경량 경로에서 클로니가 `output/summary.md` 작성자이자 게이트 3 판정자로 겹쳐 자가 판정 발생 (역할배분)
- `서술 문장 30% 이상 표본`의 표본 선정 규칙이 없어 검증자마다 커버리지 분모가 달라짐 (구체성)

## 설명
### 구체성
- 잘된점: 이전 프롬프트 `한 줄은 120자 이내로 작성, 긴 문장은 적절히 줄바꿈`의 모호어를  
  `모호어("적절히"·"잘"·"알아서"·"다수") 사용 금지`로 명시 차단하고 대체 동작을 규정함(기준 1).  
  `추출 텍스트 페이지당 평균 200자 미만 또는 총 500자 미만`, `청크 1,000~2,000자`,  
  `TL;DR 1,800자·표준 4,000자·상세 12,000자`로 임계값·단위를 전부 수치화함(기준 2).  
  `판정 과장`을 `원문의 한정어(일부·특정 조건·가능성·경향)를 삭제하거나 단정·최상급으로 격상`으로  
  조건문화해 판정자 간 편차를 제거함(기준 3)
- 보완할점: `대조 커버리지`의 `서술 문장 30% 이상 표본`에 표본 추출 규칙이 없음. `점검 2차`는  
  `무작위 3개 항목`으로 방법을 명시했으므로 동일 수준으로 `절별 균등 배분 후 각 절 내 무작위 추출,  
  절당 최소 1건`을 추가할 것. 또한 `별칭 미지원 오류 시 최신 Opus ID를 명시하여 1회 재시도`의  
  `최신 Opus ID`가 미검증 표현이며 `ID 추측 지정 금지`와도 충돌하므로,  
  `사용자에게 1회 질의 후 응답값 사용, 무응답 시 Advisor 생략`으로 확정할 것
### 실용성
- 잘된점: `실측값은 숫자·개수 기재(예: 대조 34/34), 공란·확인함 등 서술뿐인 행 1건 이상이면 미완료임`은  
  "생성됨"이 아닌 실측 수치 확인을 완료 기준으로 삼은 모범 사례임(기준 3).  
  `input/ 내 대상 파일 1개일 때 자동 선택` + `미지정 항목은 AskUserQuestion 1회로 일괄 질의`로  
  사용자 개입을 최대 1회로 압축함(기준 1). `output/summary.md`·`output/verification_report.md` 2종을  
  경로·스키마·필수 절까지 확정해 후가공 없이 배포 가능함(기준 2)
- 보완할점: `호출 상한 | 논문 요약 실행 1회당 파이프라인 위임 12회`가 `배치 단위 20쪽`과 충돌함.  
  `200쪽 초과 시 범위 확인 후 진행`이므로 200쪽 논문은 1단계에만 배치 10회가 필요해 12회를 넘기고,  
  `11 | 한도 초과 ... 즉시 중단`으로 정상 논문이 실패 종료됨. → 상한을 `기본 4 + 배치 수 + 회송 3 +  
  재호출 5`로 배치 수 연동형으로 바꾸거나 1단계 배치 위임을 상한 산입에서 제외할 것.  
  또한 `상한 400줄, 매 호출 시 전문 적재됨`이라 명시했으나 본문이 401줄로 자체 상한에 도달했으므로  
  `대화 가이드`·`운영 규칙` 절을 `references/`로 분리하고 본문에는 경로만 남길 것
### 역할별 팀원 배분
- 잘된점: 파이프라인형(`수집→분석→작성→검증`)이 작업 성격과 정합하고 팀원 경력 키워드가 배정과 1:1 대응함 —  
  도윤 `대규모 문서 ETL·OCR 파이프라인 구축` ↔ `텍스트·표·그림·수식 추출, 절 단위 청크화`,  
  지안 `장문 분석` ↔ `논점 식별, 핵심 문장·수치 추출`, 현우 `품질 검수·팩트체크` ↔ `요약-원문 대조 검수`  
  (기준 2). 이전의 서술형 R&R을 `담당 | 허용 도구 | 금지 도구 | 쓰기 허용 경로` 표로 전환하고  
  `세린 | ... | Bash, Grep, WebFetch, Agent | output/summary.md`처럼 파일 1개 단위까지 좁힘(기준 1).  
  `o: 기동 ... 팀원 4인을 Agent 도구로 1회전당 1회씩 병렬 호출`로 독립 의견 수집에 병렬을 도입함(기준 3)
- 보완할점: `클로니 | ... | output/summary.md(경량 경로 한정)`과 `판정 절차 | 클로니가 산출 파일을 실물  
  확인 후 위 표와 대조함`이 겹쳐 경량 경로에서 게이트 3을 작성자 본인이 판정함 — `작성·검증 주체 분리`  
  취지와 어긋나므로 경량 경로 게이트 3 판정도 현우에게 위임할 것. 또한 `배치 n 산출은  
  .temp/01_parsed_b{n}.md로 분리 저장`은 배치 간 의존이 없어 병렬 가능한데 순차로 기술됨.  
  `task_id: {단계번호}-{샤드식별자}(예 1-p001)` 샤드 식별자가 이미 있으므로  
  `배치 최대 4개까지 도윤 인스턴스 동시 위임`을 추가하면 200쪽 논문 1단계 소요가 실질 단축됨
