# 3회차 과제 평가 피드백 — 송종영

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 하드코딩 날짜 `게시일 2025-07-21 이후`를 `실행일(오늘) 기준 정확히 12개월 전 날짜`로 바꿔 재사용성 확보함
- `오케스트레이터가 선정·예산분배·팬아웃·팬인·취합·압축`, `팀원은 후보 도출만`으로 책임 경계를 분리함
- 완료조건을 `완료 보고 전 파일 재읽기로 문자 수를 실측해`로 격상해 실행 결과 확인 수준에 도달함
### 보완할점
- 매칭 키워드 설계상 `기능검증`·`보안검증` 관점이 구조적으로 선정 불가 상태임 (역할배분)
- `관점 균형 판정` 미통과 시 후속 액션이 정의되지 않아 파이프라인이 멈춤 (구체성)
- 조사 도구 `mcp__playMCP__naver_blog_search` 미설치·0건 시 폴백 경로가 없음 (실용성)

## 설명
### 구체성
- 잘된점: 모호어 제거가 전면적임 — 이전 `관련 전문 관점 2~4개를 선정함`이 `매칭 관점 = 위 매칭 키워드가  
  {담당IP} 토큰과 1개 이상 겹치는 관점임`, `선정 관점 수 N = min(4, 매칭 관점 수)`로 계산 가능해짐(기준 1).  
  `총 검색 결과 수신 15건 이하`, `문자 수는 유니코드 코드포인트 기준, 대시·공백·개행 포함`처럼 단위·임계값을  
  못박음(기준 2). `① 균형 분배 충족 → ② 근거 postdate 최신순 → ③ 매핑 근거 출처 수 많은 순` 타이브레이커까지  
  조건문으로 서열화한 점이 특히 우수함(기준 3)
- 보완할점: `관점 균형 판정: N=1→4, N=2→2:2, N=3→2:1:1, N=4→1:1:1:1 분배를 충족해야 통과함`에서 미통과  
  분기가 비어 있음. 광고 제거·`postdate` 게이트 통과 후보가 특정 관점에서 0개면 `추가 검색 즉시 중단함`  
  제약과 충돌해 교착됨. → `균형 미충족 시: 잔여 쿼터가 있으면 부족 관점에 1회 재검색, 쿼터 소진 시 균형  
  규칙을 완화(해당 관점 0 허용)하고 완화 사실을 매핑 표에 사유로 기재함`을 S4a에 추가할 것. 아울러 예시의  
  `bus matrix→RTL·아키텍처`가 아키텍처 매칭 키워드 `보안 SoC 구조·위협모델·키관리`와 토큰이 겹치지 않아  
  S1 규칙과 예시가 불일치하므로, 예시를 규칙대로 정정하거나 키워드에 `버스매트릭스`를 추가할 것
### 실용성
- 잘된점: 이전 `logs 디렉토리 생성 후 작성함`이 `없으면 Bash mkdir로 logs 디렉토리 생성 후 Write로 작성함`  
  으로 실행 주체까지 지정되고, `미입력 시 AskUserQuestion 도구로 담당 IP를 질의함`으로 중단 없이 진행됨  
  (기준 1). 산출물도 `logs/logs.txt` 파일 + `주제 | 관점 | 근거 URL | postdate` 매핑 표로 가공 없이  
  학습계획에 바로 투입 가능함(기준 2). 완료조건의 `파일 재읽기로 문자 수를 실측해`는 이전의 상태 기술형  
  `본문 전체 문자 수가 200자 이내이고`보다 검증 강도가 한 단계 높음(기준 3)
- 보완할점: `disallowed-tools: WebSearch, WebFetch`로 대체 경로를 차단한 상태에서 조사 도구가  
  `mcp__playMCP__naver_blog_search` 하나뿐임. MCP 미설치·인증 실패·검색 0건이면 실행 자체가 불가하나 해당  
  분기가 없고, 현 폴백 `폴백(오케스트레이션 미지원·기본값)`은 서브에이전트 부재만 다룸.  
  → `조사 도구 호출 실패 또는 유효 결과 0건 시: 파일 미작성, 실패 도구명·쿼리·사유를 응답에 보고하고 중단함`  
  을 완료조건 상단에 추가할 것. `각 항목 40자 이내` 위반 시 재작성 규칙도 없으므로  
  `40자 초과 항목은 표준명 약어로 축약 후 재실측함` 같은 교정 루프를 붙이면 재실행 없이 수렴함
### 역할별 팀원 배분
- 잘된점: 레포에 AGENTS.md가 없어 스킬·이전 프롬프트의 `[역할]` 서술만으로 판정하였음에도 배분이 잘 드러남.  
  이전은 `오케스트레이션 지원 시 관점별 서브에이전트를 단일 턴 병렬 호출함` 한 줄뿐이었으나, 스킬은  
  `오케스트레이션 지원 시(계층형)` 라벨과 함께 오케스트레이터/팀원 책임을 분리함(기준 1).  
  `(협업 패턴: 계층형 오케스트레이션 + S1→S4 파이프라인, S3에서 관점별 병렬 팬아웃)`으로 패턴을 선언하고  
  `순차 필수: S1 선정, S2 예산 분배, S4a 취합·검증, S4b 압축(앞 단계 산출 의존)`으로 근거까지 밝힘(기준 2).  
  `팀원 간 의존성 0 → 단일 턴 병렬 호출함`과 `S3 배리어(팬인)`로 병렬·동기화를 함께 설계함(기준 3)
- 보완할점: 팀원 풀 5개 중 2개가 사문화됨 — `기능검증: UVM·커버리지·회귀`, `보안검증: 사이드채널·결함주입·  
  보안인증·취약점`은 검증 방법론 용어라 `{담당IP} 토큰`(HMAC·DMA·bus matrix 등 IP명)과 겹칠 여지가 없고,  
  `무관 관점(어느 IP와도 토큰 겹침 0) 선정 금지가 N 하한보다 우선함`이 겹쳐 두 팀원은 항상 배제됨.  
  → IP 유형→관점 매핑 테이블(예: `암호 IP → 암호+보안검증`, `버스·인터커넥트 IP → RTL+아키텍처+기능검증`)을  
  S1에 추가해 검증 관점이 IP 종류로 소환되게 할 것. 또한 `팀원(서브에이전트)은 후보 도출만 담당함`이라  
  광고 필터·`postdate` 재검증이 전부 오케스트레이터에 몰리므로, `팀원이 반환 전 광고 키워드 1차 필터와  
  postdate 자가 표기를 수행하고 오케스트레이터는 재검증만 담당함`으로 1차 정제를 위임할 것
