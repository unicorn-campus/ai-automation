# 3회차 과제 평가 피드백 — 김승호

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 버스 핀 표기 차이를 표준키 `A[0]`로 정규화하는 규칙을 명문화해 거짓 FAIL 원인을 원천 제거함
- 수작업 파싱을 금지하고 `tools/dk_pincheck.py` 단일 명령으로 대체해 실행 재현성을 확보함
- `하나라도 불일치면 FAIL, 모든 뷰가 완전 일치면 PASS`로 판정 조건문을 이분법적으로 명확히 함
### 보완할점
- 완료조건이 `리포트가 생성되고` 수준에 머물러 exit 0/1 실행 결과 확인이 빠짐(실용성)
- 팀원 배정이 이전 프롬프트와 문자 그대로 동일해 도구 도입에 맞춘 재배분이 없음(역할배분)
- `최신 버전(vX.Y) 식별`의 비교 규칙(v0.9 vs v0.10)이 미정의라 버전 오판 여지 있음(구체성)

## 설명
### 구체성
- 잘된점: 이전 프롬프트의 `verilog: module {cell} ( ... ); 포트 목록`처럼 파싱 범위가 모호했던 서술을  
  `input/output/inout 선언 포트 목록 (벡터 [msb:lsb] A는 비트 A[0]..A[n]로 전개)`로, liberty도  
  `버스 비트 pin(A<0>)는 닫는 괄호 전까지 캡처`로 대체해 검증 가능한 파싱 사양으로 승격함.  
  `PASS/FAIL(exit 0/1)`처럼 기계 판독 가능한 값과 `하나라도 불일치면 FAIL, 모든 뷰가 완전 일치면 PASS`,  
  `이름·비트 인덱스·존재여부는 엄격 대조함(누락 비트는 FAIL)`로 판정 조건문을 예외까지 포함해 명시함  
  (판정 기준 1)·2)·3) 모두 충족)
- 보완할점: `{dk-root} 하위 ~~~vX.Y 중 최신 버전(vX.Y) 식별`에 비교 알고리즘이 없어 문자열 정렬 시  
  `v0.9 > v0.10`으로 역전됨. → `X·Y를 정수로 분리해 (X, Y) 튜플 내림차순 비교, vX.Y 정규식 미준수  
  폴더는 후보에서 제외하고 리포트 ④에 제외 목록 표기`로 명시할 것. 또한 `Critic: 추출·대조 결과의  
  오탐·누락을 순차 검증`에 합격선이 없으므로 점검 항목 3종(정규화 오적용·파서 잘림·버전 오식별)과  
  `1건이라도 지적 시 도구 재실행 후 재검증, 2회 연속 동일 결과면 확정` 같은 종료 조건을 추가할 것
### 실용성
- 잘된점: `핀 추출·대조·버전안내는 결정적 도구 tools/dk_pincheck.py로 실행함 (수작업 파싱 금지)`와  
  `python tools/dk_pincheck.py --cell {cell} --dir {dir} --mode {N} --latest {vX.Y} --out  
  .temp/dk-check-{cell}.md`로 LLM이 뷰별로 직접 읽어 판단하던 단계를 명령 1회로 축약함.  
  산출물도 `정합성 리포트: .temp/dk-check-{cell}.md (마크다운)`에 `① 버전 요약 ② 핀 매칭 표(핀 × 뷰,  
  누락 표시) ③ PASS/FAIL 판정 ④ 조치 필요 항목` 구성까지 고정해 가공 없이 전달 가능함  
  (판정 기준 1)·2) 충족)
- 보완할점: 완료조건이 `출력 경로에 리포트가 생성되고, 핀 매칭 표와 PASS/FAIL 판정이 채워짐`으로 생성  
  확인 수준에 머묾 — 작업방법에 `exit 0/1`을 정의해 두고도 완료 판정에 쓰지 않음(판정 기준 3) 미충족).  
  → `① 도구 exit code(0=PASS/1=FAIL)와 리포트 ③의 판정이 일치함 ② 핀 매칭 표의 뷰 열 수가 모드별  
  뷰 수(mode1=3/mode2=4/mode3=5)와 일치함 ③ FAIL 시 ④ 조치 항목이 누락 핀 건수만큼 채워짐`으로  
  실행 결과 기반 검증 3항목을 명시할 것. `미추출 시 사용자에게 CIW 실행 후 파일 경로 제공을 요청`도  
  이전 프롬프트와 동일해 mode3 수동 개입이 남으므로, `{cell}.pins.txt` 선탐지 후 CIW 실행 명령을  
  완성형으로 출력하고 파일 수신 시 자동 재개하는 흐름을 추가할 것
### 역할별 팀원 배분
- 잘된점: AGENTS.md 경력 서술과 배정 작업의 키워드 대응이 정확함 — `핀 추출가`(`EDA 뷰 포맷·넷리스트  
  파싱 12년`) ↔ `선택된 뷰에서 핀 이름 목록을 병렬 추출`, `정합성 검증가`(`표준셀 라이브러리 QA 10년`)  
  ↔ `뷰 간 핀 이름 집합을 완전 동일 기준으로 대조`, `버전 관리자`(`릴리스·형상관리 11년`) ↔ `최신 DK  
  버전 확인`. 뷰 간 의존성이 없는 추출은 `병렬` 추출, 판정에 의존하는 Critic은 `순차` 검증으로  
  병렬·순차를 의존성 기준으로 구분함 (판정 기준 2)·3) 충족)
- 보완할점: 이전 프롬프트의 `버전 관리자:`/`핀 추출가:`/`정합성 검증가:`/`Critic:` 4개 블록이 개선본에  
  문구까지 동일하게 유지되어 기존 대비 추가 분담·재배분이 없음(판정 기준 1) 미충족). 게다가 도구 1회  
  호출이 3개 역할의 실작업을 흡수해 `핀 추출가: ... 병렬 추출` 선언이 실행상 무효가 됨. → 도구를 뷰  
  단위로 분할 호출 가능하게 하고(`--view verilog|liberty|lef|cdl|gds`) `핀 추출가 서브에이전트를 뷰  
  개수만큼 동시 기동 → 검증가가 산출물 집계·대조`로 선언과 실행을 일치시킬 것. 도구화로 새로 생긴 작업  
  (파서 신뢰도 확인)은 `도구 검증가 — dk_pincheck.py 출력과 뷰 원문을 1개 셀 샘플로 교차 대조`처럼  
  별도 담당자에게 배정할 것
