# 3회차 과제 평가 피드백 — 고광진

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 기존의 `주요 데이터` 같은 모호어를 데이터 선정 3기준·`노드 20개 이하`·`3건 이상 7건 이하`로 대체함 (구체성)
- 단일 실행이던 프롬프트를 0 ~ 6단계 5개 역할로 분해하고 2단계를 `플로우 추적가 ×N | 병렬`로 실행함 (업무배분)
- 완료조건을 `불일치 0건`·`생성·수정된 파일이 0건임`·`시크릿 값 0건`의 검증 가능 지표로 재작성함 (실용성)
### 보완할점
- `대표 오류·예외 경로 1개`의 "대표" 선정 기준이 없어 실행마다 결과가 달라짐 → 선정 우선순위 명시 (구체성)
- 병렬이 2단계 1곳뿐이며 4단계 코드 대조와 리뷰 포인트 도출은 독립인데 순차임 → 분리 병렬화 (업무배분)
- `{scope} 미지정`·진입점 후보·6단계 회고로 사용자 확인 게이트 3곳 추가 → 무인 모드 옵션 필요 (실용성)

## 설명
### 구체성
- 잘된점: 기존 `주요 데이터가 어디서 생성되어 어떻게 변환·전달되는지 추적`의 "주요"를 `진입점의 입력(인자, 외부  
  입력, 설정값)`/`2개 이상의 단계(함수·모듈) 사이에서 전달되는 구조체·객체·버퍼`/`플로우의 분기 판정에 사용되는  
  상태 값`의 3택1 판정으로 대체함. 기존 `비유와 예시를 들어 쉽게 설명`도 `비유는 주요 개념 설명에 한해 섹션당  
  1개 이하`로 계량화함. `{max-depth} 호출 깊이 상한 (미지정 시 5)`, `{max-files} (미지정 시 30)`,  
  `1,000줄 초과 파일`, `무작위 3곳 이상 10곳 이하`, `한 문단 4문장 이내`, `10줄 초과 인용하지 않음`으로 단위와  
  임계값을 모두 부여함. 등급도 `HIGH(오동작·보안 사고 직결 가능) / MEDIUM / LOW`, `[근거 있음]`/`[추정]` 2등급,  
  `단일 모듈 내 분기·반복이 중심이면 flowchart, 2개 이상 모듈 간 호출 왕복이 중심이면 sequenceDiagram` 조건문임
- 보완할점: `정상 실행 경로 1개 + 대표 오류·예외 경로 1개`에서 "대표"의 판정 기준이 없어 실행자마다 다른 경로를  
  선택할 수 있음. → "심각도 HIGH 후보가 포함된 경로 우선, 동순위 시 진입점에서 호출 깊이가 얕은 경로" 같은 결정  
  규칙을 추가할 것. `무작위 3곳 이상 10곳 이하`도 문서 내 코드 위치 총 개수와 무관한 절대 건수이므로  
  "코드 위치 표기 총량의 10%, 최소 3곳 최대 10곳"처럼 비율 기준을 병기할 것
### 실용성
- 잘된점: 기존에 없던 `.gitignore`에 `flows/` 항목 확인, 없으면 추가`, `flows/ 및 flows/.work/ 디렉토리가 없으면  
  생성`, `동일 파일이 이미 존재하면 덮어쓰지 않고 순번 추가`로 준비·충돌 처리의 수동 조치를 제거함.  
  `자신의 담당 출력파일 1개(flows/.work/ 하위)에 한해 Write 사용을 허용`으로 오케스트레이터 재기록 단계도 없앰.  
  산출물이 `{출력 루트}/flows/{기능명}_{YYYYMMDD}.md (마크다운)`에 `기능명: 영문 소문자와 하이픈만 사용`,  
  `문서 필수 목차 (7개 섹션)`, `> CONFIDENTIAL — 사내 전용. 외부 공유 금지` 헤더까지 확정되어 배포 가능함.  
  기존 완료조건 `flows/ 경로에 분석 문서가 생성됨`이 `{code-path} 내부에 생성·수정된 파일이 0건임`,  
  `review-log.md)에서 불일치 0건`, `문서 내 시크릿 값 0건`으로 결과 확인형으로 바뀜
- 보완할점: `{scope} 미지정 시: 진행하지 말고 후보 진입점 목록(최대 5개)을 제시하여 사용자에게 선택 요청`,  
  `2개 이상 후보가 있거나 식별 불가 시 ... 사용자에게 확인 요청`, 6단계 `AskUserQuestion(multiSelect)`으로  
  대화형 중단점이 3곳 생겨 배치·반복 실행 시 완주가 불가함. → `--auto` 형태의 무인 모드(후보 1순위 자동 채택 +  
  선택 내역을 review-log.md에 기록)를 추가할 것. mermaid도 `자체 점검 체크(노드 ID 중복 없음, 화살표 문법 정상,  
  예약어 회피) 통과`까지만 규정하고 `최종 렌더링 확인은 사용자 몫`이어서 렌더 실패가 완료조건을 통과하므로  
  "허용 문법 화이트리스트 대조" 같은 대체 검증 절차를 완료조건에 넣을 것
### 역할별 팀원 배분
- 잘된점: 기존 프롬프트는 역할 분담 없는 단일 실행이었으나 `[1단계 | 구조 분석가 | 순차]`,  
  `[2단계 | 플로우 추적가 ×N | 병렬]`, `[3단계 | 문서 작가 | 순차]`, `[4단계 | 검증자 | 순차]`로 5개 역할에  
  분담하고 `역할 정의: 대규모 코드베이스 지도를 그리는 정적 분석 전문가` 등 페르소나를 부여함.  
  `협업 패턴: 계층형 — 오케스트레이터가 작업을 분해·위임하고 최종 산출물을 통합함`이 AGENTS.md 오케스트레이터의  
  `서브에이전트 태스크 분배·조율, 팀 방향성 수립 및 최종 산출물 통합`과 키워드 대응하며 0·5·6단계 배정이 실제로  
  그 서술과 일치함. `작성자와 다른 서브에이전트로 수행`으로 검증 독립성도 확보함. 병렬화는 `동시 실행 (기본 3개,  
  최대 5개, 5개 초과 시 5개씩 배치로 나누어 순차 실행)`과 `Agent 도구를 한 메시지에 복수 호출`로 방법·상한을 함께 규정함
- 보완할점: 4단계 검증자가 `무작위 3곳 이상 10곳 이하를 원본 코드와 대조`와 `코드 리뷰 포인트 정리: 3건 이상  
  7건 이하`를 동시 수행하지만 두 작업은 상호 의존이 없음. → 대조 담당과 리뷰 포인트 도출 담당을 분리해 병렬  
  배정하면 4단계 지연을 줄일 수 있음. 2단계 플로우 추적가가 `실행 플로우`와 `데이터 플로우`를 함께 담당해 단위당  
  부하가 크므로, 실행 체인 추적과 데이터 생명주기 표 작성을 서로 다른 역할로 나누되 `타 단위로의 제어 이관 지점  
  명시` 결과를 공유 입력으로 넘기는 파이프라인 조합을 검토할 것. AGENTS.md 멤버가 오케스트레이터 1명뿐이므로  
  구조 분석가·플로우 추적가·문서 작가·검증자를 멤버로 등재해 위임 근거를 일치시킬 것
