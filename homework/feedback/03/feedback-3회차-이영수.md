# 3회차 과제 평가 피드백 — 이영수

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

> 특이사항: `SKILL.md` 본문이 frontmatter를 제외하면 제출 `이전프롬프트.txt`와 `seq=1.000`(바이트 단위 동일).  
> 타인 제출물과의 유사도는 전 쌍 0.05 미만이므로 복제 아님. 3개 관점 모두 판정 기준 1)  
> ("기존 프롬프트 대비 개선")이 미충족 처리됨

## 요약
### 잘된점
- 판정 유형을 `T1 ~ T5` 표로 사상하고 exit code `0`=PASS/`1`=FAIL/`2`=INCONCLUSIVE 규약을 고정함 (구체성)
- AGENTS.md 실재 팀원 5명에 파이프라인형 4단계 + 1단계 병렬 3인을 배치해 배분 근거를 명시함 (업무배분)
- 완료조건을 `미확보 건수가 ... 합과 일치함이 확인됨` 등 제3자 검증형으로 기술함 (실용성)
### 보완할점
- 3개 관점 1)번 기준 공통 미충족 — 본문이 이전프롬프트와 동일해 "개선분"이 0건임 (구체성·업무배분·실용성)
- 판정 코드가 `raise NotImplementedError("구현 필요")` 8곳이라 주니어가 수동 구현해야 함 → 최소 1개 완성 (실용성)
- `DFT 엔지니어(스캔)` 담당 항목을 `범위 외 — 별도 위임 필요`로만 표기 → 잔여 예산으로 배정 (업무배분)

## 설명
### 구체성
- 잘된점: 모호어 대신 측정 가능한 임계값을 전면 사용함 — `도구 호출 예산 총 30회 이내: Read 13 / Grep 5 /  
  Glob 3 / Agent 6`, `1인당 40줄·1500자 이내`, `문서 총 300줄 이내`, `앵커 ±20줄만 부분 읽기`.  
  등급·조건 분기도 `P0`/`P1`, `HIGH/LOW`, `T4의 "종료 사이클 미검출"은 FAIL이 아니라 INCONCLUSIVE로 분류함`으로  
  명시됨. `(anti-example — 아래 형태는 금지)` 절에 `"빠르게 수행"·"10분 초과 금지" → 측정 주체·지표가 없어 검증  
  불가함`을 스스로 배제한 점도 근거임
- 보완할점: 이전프롬프트와 본문이 동일해 모호어 대체 이력이 존재하지 않음. 자체 수치 간 충돌도 남음 —  
  `문서 총 300줄 이내`인데 `[출력]` 7번 섹션이 요구하는 Python 코드블록 예시만 128줄이며 10개 섹션이 추가되므로  
  상한 초과가 구조적으로 발생함. → `300줄 이내(코드블록 제외)` 또는 `500줄 이내`로 재산정할 것.  
  `{칩프로젝트명} (미지정 시 문서에 자리표시자를 유지함)`도 출력 경로  
  `docs/rom-code-verify-setup_{칩프로젝트명}_{YYYY-MM-DD}.md`에 그대로 대입되면 중괄호 리터럴 파일명이 생성되므로  
  `미지정 시 파일명은 UNSPEC로 치환` 같은 대체 규칙을 명시할 것
### 실용성
- 잘된점: 산출물 형식이 경로·확장자·섹션 개수까지 확정됨 — `경로: docs/rom-code-verify-setup_{칩프로젝트명}_  
  {YYYY-MM-DD}.md (Markdown 1개 파일, 신규 생성)`, `섹션 구성 (번호·순서 고정, 총 10개)`.  
  완료조건이 생성 확인을 넘어 내용 검증 수준임 — `Python 코드블록에 sys.exit(main())과 EXIT_PASS = 0/  
  EXIT_FAIL = 1/EXIT_INCONCLUSIVE = 2 규약이 포함됨이 확인됨`, `32자 이상 hex 리터럴 중 출처 표준명·섹션이  
  병기되지 않은 건이 0건임이 확인됨`. `AskUserQuestion 1회로 묶어 최대 4문항까지 질의`와 `회신 대기 금지`로  
  대화 왕복도 1회로 제한함
- 보완할점: 실질 갭은 산출물이 즉시 실행 불가 상태라는 점임 — `판정 코드는 7번 섹션 코드블록으로만 제시하며  
  별도 .py 파일 생성 없음`이고 코드 골격이 `raise NotImplementedError("구현 필요")`·  
  `return (False, "미구현 — 구현 필요")`로 채워져 있어, `[맥락]`이 선언한 `2년차 주니어 HW 엔지니어`가  
  `문서만 읽고 ... 착수 가능한 수준`에 도달하지 못함. → `check_magic`·`check_cycle` 2개는 완성 코드로 제시하고  
  나머지는 골격 유지로 절충할 것. 완료조건에 `문서에 1 ~ 10번 섹션 헤더 10개가 모두 존재함이 확인됨`처럼 존재  
  확인만 남은 항목은 섹션별 최소 행수·필수 키워드 조건을 덧붙여 빈 헤더 통과를 막을 것
### 역할별 팀원 배분
- 잘된점: 배정 작업과 AGENTS.md 경력·성향 서술의 키워드가 정확히 대응함 — 크립토는 성향이 `알고리즘 구현 전  
  표준 스펙과 공식 테스트 벡터 확보를 최우선으로 함`인데 `공개 KAT 벡터 출처(표준번호·섹션)와 기대값 표`를 배정,  
  아키는 역할이 `팀원 간 인터페이스 정합성 검토`인데 `4건 산출물의 인터페이스 정합성 ... 검수`를 배정함.  
  `1단계 (병렬 위임, 동시 3명, 1개 메시지에 Agent 호출 3건 동시 발행)`에 `3인은 서로의 결과를 보지 않고 동일  
  공통 입력만 받음 — 상호 독립 영역이므로 병렬 배치에도 정합성 손실 없음`으로 독립성 근거를 제시하고, 반대로  
  2단계에는 `순차 고정 근거: 판정 스크립트는 게이트의 로그 포맷 ... 확정된 뒤에만 파싱 로직을 특정 가능`으로  
  순차 사유를 남김
- 보완할점: 잔여 결함 3건임. ① AGENTS.md에 실재하는 `DFT 엔지니어`(스캔)를 미배정하고 `대책 설계는 9번 섹션에  
  범위 외 — 별도 위임 필요로 표기함`으로 넘김 — `Agent 총 호출 6회 이하` 예산에 재위임 1회 여유가 있으므로  
  스캔에 JTAG 락다운 관측 항목 1건을 배정할 것. ② `[작업방법]`은 `해당 팀원의 닉네임·성향·경력을 위임 프롬프트  
  [역할]에 기입함`을 요구하나 스킬 `[역할]` 섹션은 `- 게이트: RTL 설계 엔지니어 (디지털 IC 설계 10년, ASIC·FPGA  
  테이프아웃 경험 보유)`처럼 경력만 담아 성향 원문이 없음 — AGENTS.md 성향 1줄을 팀원별로 함께 인용할 것.  
  ③ `HIGH로 분류된 항목에 한해 해당 팀원 1명에게만 재위임 1라운드를 허용함`은 HIGH가 2명 이상에 걸릴 때 처리  
  규칙이 없으므로 `HIGH 복수 시 영향 범위가 넓은 1건만 재위임하고 잔여는 10번 섹션에 미해결로 기재` 같은 선택  
  규칙을 추가할 것
