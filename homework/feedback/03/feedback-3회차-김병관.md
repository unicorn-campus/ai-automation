# 3회차 과제 평가 피드백 — 김병관

> 평가 관점: 구체성 개선·업무 배분 개선·실용성 개선 3개  
> 평가 기준: 각 스킬 `[역할]` 섹션에 명시된 전문가 역할. 형식·섹션명 준수 여부는 평가 대상 아님  
> 모든 지적은 제출한 스킬·이전 프롬프트 원문의 실제 문구에 근거함

## 상세 피드백

#### 과제1 — 스킬 제작·개선

## 요약
### 잘된점
- 검증 게이트를 `허용오차 1e-6`·KAT 앵커 `Assessed = 5.8608937444852494`로 수치 고정함 (구체성)
- 산출물 비의존 작업을 `[병렬 웨이브]` 3개 Task 동시 위임으로 분리해 대기시간을 제거함 (업무배분)
- 완료조건을 `클로니가 직접 재실행한 N passed 로그` 첨부로 규정해 실행 증거 없는 완료를 차단함 (실용성)
### 보완할점
- `AIS 31 [PTG.2 / PTG.3]` 선택 경로에 대조 참조값·게이트가 없어 판정 공백 발생 → 별도 게이트 정의 (구체성)
- `[게이트 A: 계층형] 스탠다 — 2트랙 병렬`은 1인 병렬로 패턴 라벨이 뒤섞임 → 트랙2를 큐에이로 이관 (업무배분)
- `2회 초과 → 3자 병렬 위임` 이후 미수렴 종료조건이 없어 루프 위험 → 에스컬레이션 조건 추가 (실용성)

## 설명
### 구체성
- 잘된점: 이전프롬프트의 판정 기준은 `추정기 결과가 참조 구현/시험벡터와 일치`와 예시 내 `±0.01 bits/sample`  
  수준이었으나, 스킬은 `게이트 | **허용오차 1e-6**(NIST selftest 기준)`으로 임계값을 본문에 승격함.  
  측정 단위·규모도 `10K 3종 + 1M 4종`, `alph=179`, `실측 9분 19초`, `pytest FAST 60 passed`로 명시됨.  
  판정 조건문도 `|Δ| > 게이트면 불일치 → 트로피 반려(상한 2회)`, `소규모 KAT 미통과 시 1M 실행 금지`,  
  채택식 `Assessed = min(H_original, word_size × H_bitstring)`으로 확립됨
- 보완할점: `표준·track | SP800-90B + AIS 31 [PTG.2 / PTG.3 / 미포함]`으로 AIS 31 선택지를 열어두었으나  
  §0 검증 gold는 `.temp/nist_ref/cpp/selftest/refdata/*.res`뿐이고 완료조건도 `게이트(1e-6) 이내로 참조값과 일치`만  
  규정해 AIS 31 채택 시 대조 대상이 정의되지 않음. → AIS 31 선택 시 `PTG.2 T0~T8 판정표 + 수용구간`을 별도  
  완료조건 행으로 추가하거나 선택지에서 제거할 것. `성능 판정: 1M wall-clock 측정·기록, 사용자 성능 요건 대조`도  
  기본값이 `제한없음`이어서 판정 불가 구간이 생기므로 `기본 임계값 = 1M non-IID 전체 ≤ 15분` 등 디폴트를 명기할 것
### 실용성
- 잘된점: 이전프롬프트는 `<개발요청>`에 `{...자유롭게 입력하세요}`만 두어 사용자가 스펙을 직접 작성해야 했으나,  
  스킬은 §1에서 8개 필드를 `선택지 + 기본값`(예: `추정기 | ... | non-IID 10종 전체`)으로 제시해 무입력 진행이  
  가능해짐. §0가 `git clone --depth 1 ... .temp/nist_ref`와 `**C++ 재빌드 불필요**`, `반드시 python3`를 사전 고정해  
  환경 탐색 개입도 제거함. 산출물은 `docs/01-standard-spec.md`, `docs/03-verification-report.md`,  
  CLI `서브커맨드 4종 non-iid / iid / restart / conditioning`으로 경로·형식까지 지정됨. 완료조건은  
  `§0 KAT 앵커 재현`, `CLI/API 실행 로그 1건 이상 첨부`, `하네스 sanity: 의도적 오답 주입 시 FAIL 발생 확인`임
- 보완할점: `2회 초과 → 3자 병렬 위임(스탠다 유권해석·트로피 로직·큐에이 참조값)` → `클로니가 근본원인 수렴`까지만  
  있고 수렴 실패 시 출구가 없어 반복이 무한정 연장될 수 있음. → `3자 위임 1회 후에도 |Δ| > 게이트면 해당 추정기를  
  FAIL로 확정하고 미해결 항목에 기록 후 사용자에게 게이트 완화 여부 질의`처럼 종료 규칙을 §2에 명시할 것.  
  §1의 8개 필드를 `AskUserQuestion`으로 수집하라고만 지시하는데 해당 도구는 1회 문항 수 상한이 있으므로  
  `1차(표준·track, 추정기, 산출 형태, 언어) / 2차(추가 시험, 입력 형식, 성능, 게이트)`로 호출 회차를 규정할 것
### 역할별 팀원 배분
- 잘된점: 이전프롬프트는 `1.스탠다 → 2.트로피 → 3.큐에이 → 4.리포 → 5.통합` 순차 5단계였으나, 스킬은  
  `상위 뼈대는 **파이프라인형**, 하위에 실전에서 확인된 병렬·협업·반려 패턴을 배치함`으로 재구성하고  
  `게이트 A 완료 후 3개 Task 동시 위임`을 도입함. 병렬 근거도 `큐에이(검증 준비) [입력=refdata, 트로피 산출물  
  비의존]`으로 의존성 기반임. AGENTS.md 경력과 배정 작업의 대응도 성립함 — 트로피 `대용량 원시 표본(≥1,000,000  
  샘플) 처리 파이프라인 설계 경험` ↔ `1M 경로 벡터화, t-Tuple/LRS는 suffix array`, 큐에이 `"동작한다"가 아니라  
  "참조값과 일치한다"로만 완료를 판단함` ↔ `트로피 self-check를 **신뢰하지 말고 직접 재실행**`
- 보완할점: `[게이트 A: 계층형] 스탠다 — 2트랙 병렬`은 AGENTS.md의 계층형 정의 `팀원 1명 위임 → 클로니가  
  검수·통합`과 병렬 실행이 한 라벨에 혼재해 실행 형태가 모호함. 특히 `트랙2(환경): §0 clone 실행,  
  refdata/*.res·bin/*.bin 존재 검증`은 스탠다 경력 `암호모듈 검증(KCMVP·CMVP) 표준 준수 분석 전문`과 무대응임.  
  → 트랙2를 큐에이(`시험벡터 설계·자동화 회귀 시험 구축 경험`) 또는 클로니 직접 수행으로 이관하고 라벨을  
  `계층형(스탠다 명세) + 클로니 직접(환경확보) 병렬`로 정정할 것. 이전프롬프트에 있던 토론형이 §2에서  
  `2회 초과` 예외 경로에만 남았으므로 수용기준 합의 구간에 토론형 라운드를 상시 배치할 것
